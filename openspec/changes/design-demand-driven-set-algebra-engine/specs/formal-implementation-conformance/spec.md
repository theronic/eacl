## ADDED Requirements

### Requirement: Formal completion precedes production operator implementation
Production implementation or routing of intersection and exclusion SHALL NOT begin until the extended semantic, stratification, candidate-cover, witness, ordering, resume, vector, specialization, recursive-join, negative-evidence, cache, and bounded-work proof suites verify successfully under the locked toolchain. REPL experiments and isolated non-production prototypes MAY precede proof completion but MUST NOT become public engine authority.

#### Scenario: Proof suite is incomplete
- **WHEN** any mandatory operator proof, mutation control, or obligation pin is missing or failing
- **THEN** implementation tasks that modify production evaluator or routing namespaces remain blocked

### Requirement: Every operator-affecting production decision is mapped
Every parser normalization, signed-graph decision, plan selection, candidate transition, witness application, Boolean reduction, join-state update, negative decision, page boundary, cache action, and typed failure reachable from a public operator request SHALL route through generated authority or a source-digested specialization with complete abstract-case equivalence.

#### Scenario: Handwritten fast path lacks refinement
- **WHEN** a Datahike-specific or host-language operator fast path can affect a decision or boundary without a registered refinement
- **THEN** the complete-public-engine assurance claim remains incomplete and production routing stays disabled

### Requirement: Proof artifacts and generated runtimes are reproducible
The release gate SHALL pin formal sources, tool versions, obligation counts, generated Java and JavaScript digests, CLJ/CLJS bridge vectors, specialization source closures, adapter assumptions, mutation controls, and the project-operator authorization and assurance evidence for operator support. If independent review has not been performed, that absence SHALL remain an explicit qualification and MUST NOT be represented as completed review.

#### Scenario: Generated source changes
- **WHEN** an operator model edit changes generated output or theorem obligations
- **THEN** stale manifests and bridge digests fail validation until deliberately regenerated and reviewed

### Requirement: Independent executable oracles remain outside production authority
Finite-set, naive Kleene, materializing lookup, and SpiceDB differential oracles SHALL be structurally independent from the optimized production evaluator and SHALL be used for counterexample discovery and refinement replay rather than imported as production decision code.

#### Scenario: Optimized and oracle results diverge
- **WHEN** randomized differential execution finds a result, order, boundary, or failure mismatch
- **THEN** the seed is retained and operator release remains blocked
