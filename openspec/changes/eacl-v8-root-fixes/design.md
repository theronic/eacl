# Design: EACL v8 root-cause fixes

## Context

EACL v8 (pre-release, `release/v8.0` lineage, audited at `codex/restore-v8-enumeration-performance @ 8b17ee0`) ships a Dafny-generated decision kernel as its only engine, a two-axis cache (exact/managed × answers/projections/denotations), keyset+ordinal cursors, and three backends of which two are a fork pair. Two audit waves (six deep dives, ten adversarial verifiers, a three-question strategy-loophole wave — all recorded in `docs/reports/2026-08-07-eacl-v8-exploration-review.md` Parts I–II and the workflow records) established ten root causes (proposal R1–R10) with file:line evidence, several empirical repros (a reproduced single-flight deadlock; instrumented double schema proofs; a measured 95.5 MB unbounded answer tier; a stale-ALLOW on DataScript's default configuration), and verified fix designs. The 0tx consumer report supplies the motivating workload: populated recursion through the raw API, 38.1×/12.1×/9.1× vs v7.

Constraints: v8 is pre-release — cursor/token formats, defaults, and module structure may break. The project's invalidation philosophy holds: only EACL's write API signals invalidation, via in-database stamps; no content digests, no transaction listeners, no derived detection on the write path (issue #74). The Dafny authority remains authoritative on every decision path, or the change must state the new certification story explicitly.

## Goals / Non-Goals

**Goals:**
- Eliminate the two correctness defects (cursor skip/dup on the recursive route; single-flight deadlock) with mechanisms that are proven or deterministically tested, not plausible.
- Recover the 0tx populated-recursion regression to ≤2.0× matched v7 without answer caching, with a path to parity.
- Make cache validity uniformly dependency-scoped (answers, subproblems, cursors — one mechanism), and make every cache byte-bounded with honest eviction.
- Collapse the backend fork onto the SPI; one orchestration, one filter validator, one codec family.
- Make the browser path production-real: `:advanced` compiles, no BigNumber hot path, absolute perf ceiling.
- Convert every fix into a ratcheted logical-work gate so regressions are deterministic CI failures, not benchmark noise.

**Non-Goals:**
- SpiceDB feature expansion (intersection `&`, exclusion `-`, wildcards, `subject_relation`, caveats — issues #44/#10/#9 stay open; the union+arrow fragment remains the product).
- Endpoint-local (per-tuple) invalidation stamps — deferred until relation-granularity stamps measurably thrash on a real workload.
- Adaptive cache sizing policy — the telemetry this change adds is its prerequisite; the policy is a follow-up.
- Changing the JVM engine strategy — generated Dafny→Java stays the JVM authority.
- Managed-by-default on any backend (revisit only after the randomized managed oracle has soaked).

## Decisions

### D-1. Single-flight: hardened owner-acquires-first ("i-b")
Restructure `subproblem_cache.cljc` so the computation slot is acquired strictly **before** the flight owner's deref, and the flight delay body runs under `(binding [*computation-owner* (execution-context)] (compute))` so **any** body-runner — including a joiner that steals an unrealized body (Clojure `Delay` runs its body on whichever thread derefs first) — carries the re-entrancy skip for all nested resolves.

Why this over the alternatives (all three were adversarially analyzed; two wedge-schedules were constructed):
- *Literal owner-acquires-first* still wedges via body-stealing: a permit-less joiner steals the body and parks on a nested owner-path acquire while holding the stolen delay's monitor.
- *Release-while-joining* works but has three sharp edges (unbind-around-deref, per-coordinator permit tracking, interrupt-safe re-acquire — a failed re-acquire plus the body's `finally` release *mints permits*), and inflates latency via requeue-per-join.
- *Timed-acquire + inline fallback* cannot wedge but erodes the `max-inflight` bound unboundedly exactly under saturation; retained only as an optional watchdog metric loop that never bypasses.

Soundness rests on the verified key-dependency rank function (exact-denotation → managed-denotation → exact-projection → managed-projection/proof → leaf; denotation computes never resolve another denotation key because plans compile the full rule closure and call back only into projection scans). Guards: the invariant documented on the coordinator, the deterministic wedge-schedule regression test (the exact schedule that freezes current code), and a 16-thread randomized soak with permit/active/flights leak assertions — both in the per-push suite. New metric: `:stolen-computations` (bounded overshoot in the steal window is accepted and observable). *Implementation note (deviation from the original A1 sketch): the proposed dev-mode `(assert (empty? *resolving-keys*))` at the acquire site is unsound — Clojure's binding conveyance hands `*resolving-keys*` to child threads spawned inside computes, and such children legitimately acquire their own slots while holding no delay locks (behavior pinned by the pre-existing `inherited-future-bindings-do-not-inherit-a-computation-slot-test`). The structural `nested-owner?` guard carries the same-thread invariant; the assert was dropped.*

### D-2. Recursive pagination: keyset order via probe-then-continue
Both routes emit `:lookup-eid` keyset cursors over strictly-ascending internal EIDs; the ordinal cursor kind, its rebase chunk orchestration, and the direction-unscoped recursive page cache are deleted. Sorting happens at the host on the completed denotation; every emitted slice passes through the **existing certified `DecideAcyclicPage`** (its `StrictlyOrderedAcyclicEids` precondition plus host revalidation already certifies per-slice order), so Phase A needs **no new Dafny**.

The materialization strategy is **probe-then-continue** (this corrects the naive materialize-always design, which verification showed would regress raw page-1 by 16–100× and make >100k-grant denotations unpageable raw):
1. Run the machine with `RenderPage(S)` exactly as today, minting no cursors from traversal order.
2. If `has-next?` is false, the delivered items are the complete fixed point (the machine's early-stop means the queue exhausted) — sort ≤S items; cost identical to today. This covers the dominant raw shapes (reverse "who can read X", any result that fits one page).
3. If `has-next?` is true, call the verified `Continue*Page` on the same state with window = `max-derived-grants` — continuation preserves queue/seen/emitted, so completion costs closure-minus-probe with zero replay — then sort, binary-search slice, and (store-bound) publish.

Explicitly kept: the kernel's render early-stop (counts with `:count-limit` and boolean `can?` renders depend on it) and `Continue*Page`/`continue-indexed-page` (the probe-then-continue path is its new caller). Explicitly rejected: a cursor-less traversal-order page-1 fast path — feeding a traversal-order boundary into keyset binary search produces deterministic skip/dup even on an unchanged snapshot, and it forks page-1 content between store and no-store paths.

Consequences by design: store-bound `can?` membership becomes binary search (O(log n)); recursive counts publish denotations on miss; bare `:last` and `:desc` become uniform; cursors become route-change tolerant; rebase becomes binary-search membership per the FORMAL-047 contract (hit → exclusive resume `:rebased`; miss → restart `:restarted`). The accepted trade: raw no-store page-1 on results larger than the page pays closure-minus-probe — the irreducible price of sorted first pages — mitigated by D-3 and by 0tx attaching a request store or client. A release note makes the >`max-derived-grants` raw cliff actionable. Phase B (deleting the now-dead Dafny: `RebaseCursorBound` family, backward-render mode, `AfterCursor` arm; retargeting `Pagination.dfy`) trails at leisure — dead generated ops are simply never invoked.

### D-3. Raw path: request-local context + adapter proof memo + nil-store gates
Three composable host-only changes (verified against the double-read/double-compile instrumentation):
1. A `delay` on the zero-arity `:schema-proof` inside `make-adapter` — one edit covers all backends and every read site (including `make-schema-cache`'s own double read); justified by the adapter certification suite's existing demand that repeated reads on one instance be equal. Raw list/count drops 2→1 proofs; client drops 3→2.
2. `request-schema-cache` bound by the raw facades: activates the seven memo atoms (one plan compile+certify per request, cold path walks collapse to one per unique node) with `:request-local? true` and **deliberately no `:traversal-analysis`** so raw routing keeps today's per-root classification — avoiding both a silent certified-path switch and a whole-schema-analysis regression on large schemas.
3. Nil-store short-circuits on the four denotation lookup/resolve fns, mirroring the pattern the publish fns already use, so no cache-key or dependency-closure work runs against absent stores.
Isolation invariant: publication scope = request scope = one immutable database value; speculative/filtered/historical values get fresh context; no cross-request registry is touched; write-schema! remains the only cross-request invalidation signal.

### D-4. Cursor validity: dependency-scoped proofs, unconditional schema check, one codec
Cursor continuation proofs switch from `basis-t` digests to the managed dependency-stamp descriptor the cache already computes (schema stamp + sorted per-relation stamps). `PageWindow.DecideContinuation` keeps its shape — it compares two opaque proof strings — so unrelated writes yield `UseCurrent` and the heads/continuation caches survive churn. The schema-generation check runs unconditionally on acceptance (today it is bypassed exactly when it could fire, and its stamp is a `basis-t` proxy — both fixed: the stamp becomes the schema mutation identity). All verified-decision inputs become computed values (no literal `true`/`false` placeholders). One codec: the AEAD (AES-GCM) format becomes the portable cursor codec (host crypto on JVM; WebCrypto/pure-JS on CLJS per the existing secure-format capability pattern), deleting the HMAC-only path and the two-threat-model split; defaulted keys warn at construction; the GCM nonce bound is documented.

*Implementation status of the codec unification (6.4), recorded during apply:* **deferred with cause**. Sync AES-GCM on CLJS is not implementable responsibly inside this change: WebCrypto's SubtleCrypto is Promise-only (incompatible with the synchronous client surface), Closure's `goog.crypt` has no GCM, and hand-rolling GHASH in JavaScript is exactly the crypto-authorship risk the trusted-boundary policy exists to avoid. Correctness-first ranking: a documented HMAC-authenticated (unencrypted) portable cursor beats an ad-hoc GCM. The spec requirement stands as an open item gated on either an async client surface or a vetted vendored GCM; the confidentiality split is documented loudly in the release notes, and the defaulted-key startup warning (6.5) shipped. Groups 6.1–6.3 landed with six recorded micro-deviations (batch `:relation-proof` reads; one shared 3-value graph coding preserving certified exact recovery; the proof-mode-independent schema stamp; schema-less navigation boundary keys preserving the proof-read envelope; kernel-ordered scope-before-expiry on one corner case; defensive restart on equal-proof boundary retraction).

### D-5. DataScript coherence authority: flip the default to `:unknown`
Uniform fail-safe default across all three backends; `:managed` is an explicit, documented, audited opt-in everywhere. Verified basis: the stale-ALLOW repro on the current default (one raw `ds/transact!` retraction → cached ALLOW); exactly one shipped test asserts the old default; the "guarded default" alternative is unimplementable within the #74 philosophy (the stale case is a cache-validation *success* — no failure hook fires — and a raw retraction leaves no datom to inspect without content digests). Costs accepted: contract-honoring DataScript apps lose cross-write reuse until they opt in (silent-but-safe; docstring/README updated with the one-keyword opt-in), and stock writers stop minting zed tokens (fails loud at point of use). A pinning regression test encodes the adversarial sequence.

### D-6. Answer cache: fold into the weighted SubproblemStore
Completed answers become a third tier of the subproblem store, inheriting weight budgets (byte-bounded, per-entry ceiling, oversized-rejection metric), amortized LRU, exact/managed layering via `resolve-layered-bound!`, single-flight (post-D-1), and metrics. `bounded-assoc`, `admit-entry?`, `install-managed-generation!`, and the duplicated exact/managed branches are deleted. Projection and denotation tiers stay separate from each other (different completeness semantics; `PartialRecursiveDenotationNeverHits` is what the separation buys).

### D-7. Backend de-fork: one orchestration over the SPI
The nine public operations, snapshot-context assembly, cursor plumbing, cache wiring, filter validation, integrity reporting, and endpoint codec usage move to core, parameterized by the 21-operation SPI plus per-backend construction options. Datomic's private relationship-page reimplementation moves onto `eacl.engine.relationships`. The shared anchor validator adopts value-presence (`some?`) semantics with `:nil-anchor-keys` ex-data, and nil-valued type/relation filters throw instead of wildcarding. What stays per backend (~2,100 lines measured): index-scan primitives, schema/attribute installation, transaction submission, consistency selection. Datahike additionally gains the weighted provider-store tier it accidentally lacks. Option-map unification: one token-key family, one cursor-TTL name, uniform unknown-option errors; per-backend extensions explicitly documented.

### D-8. CLJS engine: differentially certified CLJC kernel for the browser; generated Java stays on the JVM
The browser hot path stops executing the BigNumber foreign-lib. Chosen mechanism: promote the existing handwritten CLJC engine (currently the test oracle in `formal/smoke/`) to the CLJS production kernel, certified by the full existing rig — cross-runtime vectors, 62-case counterexample replay, mutation controls, randomized differential oracle, all running against the CLJS engine in CI. The switch point is the `:cljs` branch of the kernel default. Rationale: measured 5–25× JVM-vs-JS generated-kernel gap, 97× shim+BigNumber element-read overhead, 591 KB unshakeable payload, broken `:advanced`; the differential infrastructure already exists and already certified this engine before commit `d96bc4c` demoted it; browser authorization is advisory in the deployment architectures EACL targets (the server re-checks). Recorded alternative if a single engine everywhere becomes mandatory: widen `{:nativeType}` across the traversal modules (the boundary already enforces the safe-integer range), replace the Proxy rope with explicit accessors, emit ESM + externs — a proven-per-benchmark path from ~31 µs to low-single-digit µs/result that keeps codegen. Either way: a CI `:advanced` build job and an absolute ns/result ceiling gate are added (both absent today), and the artifact-size gate baselines are re-anchored (browser baseline is 43% stale; JS-with-runtime headroom is 0.87%).

### D-9. Kernel boundary: host amortizations now; wave batching only on measured need
Phase 1 (no Dafny): marshal `IndexedLimits`/fuel once per traversal, key the type catalog by raw `DafnySequence` (skip per-command string decode), intern empty responses (with an assertion that generated code never mutates a received response sequence — the collection shims' mutate-on-construction pattern makes this worth pinning), drop the host per-value walk in favor of the certified kernel validator, JVM and CLJS in lockstep. Measured expectation: ~1.5–2× on active recursion; combined with D-2/D-3, the 0tx gap should land inside the 2.0× gate. Phase 2 (wave-batched scan protocol — drive returns a bounded command batch, resume folds ordered responses; ~2×⌈streams/batch⌉ crossings) activates **only if** the populated-recursion latency gate still fails with phases D-2/D-3/D-9.1 landed; its proof plan (pending-scans generalization of the coverage invariants via the ghost-view trick; fuel-exhaustion returns Yielded without publishing partial batches so emission order stays a function of configuration, not scheduling) and its cursor-digest version bump are specified in the workflow record and stay parked until triggered.

### D-10. Gates first, fixes ratcheted
The counters (kernel crossings by op, backend ops by key, denotation-key builds, cold path walks — all no-op-when-unbound observers) and the populated-recursion suite land **before** the fixes, with envelopes recorded at current truth (schema proofs raw 2 / client 3; plan compiles 2–3; nil-store key work 2; star-2k crossings law). Each fix PR then tightens one recorded number. Matched-v7 baselines are recorded per host-class against the pre-v8 commit with the same harness; logical work stays authoritative over wall-clock per the FORMAL-048 lessons (fresh bounded JVM, gates measured first). The dormant `apalache-mutation-control` and explorer gates get wired in the same PR, and the mutation ledger is regenerated (103 vs 96 drift).

## Risks / Trade-offs

- [Acyclicity of the flight key graph is convention, not mechanism] → dev-mode assertion at the acquire site, documented invariant naming the rank function, deterministic wedge test + randomized soak in the per-push suite; any future in-compute denotation resolve fails the assertion immediately.
- [Raw no-store page-1 on large recursive results pays closure-minus-probe; >100k-grant denotations become unpageable raw] → probe-then-continue confines the cost to results larger than the page; actionable `:limit-exceeded` error text; 0tx guidance (request store or client for reads); D-9.1 shrinks the closure's constant factor.
- [Probe-then-continue needs a small engine helper for to-closure continuation windows] → the Dafny contract already permits independent window sizes; if the input-validation path rejects it, the fallback restarts materialization and wastes only the probe (~2 seeks + ~S emissions) — never wrong, only marginally slower; verified during implementation.
- [Sort-as-permutation is trusted host code] → strict-ascending validation at every cache read, count-preservation assert at the sort site, per-slice certified ordering via `DecideAcyclicPage`, differential suites; net trust decreases versus the deleted handwritten chunk orchestrator.
- [Cursor-format and default-authority breaks hit early adopters] → pre-release is the sanctioned window; typed `invalid-cursor` failures, one-keyword `:managed` opt-in, release notes rewritten; doing this after 8.0 would require the dual-format machinery the release notes explicitly refused.
- [De-fork churn across three modules could destabilize near release] → the shared contract suites (adapter certification, contract-support, state-trace differential) run per push; the de-fork lands as move-then-delete with behavior pinned by the unified filter/error tests written first.
- [CLJS engine swap changes the browser trust story] → certified by the same oracle rig that gates the JVM engine, in CI; the browser posture (advisory, server re-checks) is documented; the nativeType alternative stays recorded if the posture changes.
- [Batching proof effort (if triggered) overruns] → explicitly conditional; ghost-view mitigation bounds it; solver-brittleness noted in the two largest proof files; never blocks the correctness fixes.
- [Estimates are extrapolations] → every performance claim lands behind a recorded gate; the gates, not the estimates, are the contract.

## Migration Plan

Pre-release: no data migration. Storage layout (v7 relationship tuples) is untouched. Sequenced landing (matches tasks.md): gates/counters → single-flight → raw context → boundary phase 1 → keyset recursion → cursor validity → answer-cache fold-in → managed certification + default flip → de-fork → CLJS engine → hygiene/Dafny cleanup → (conditional) batching. Each step keeps the full suite green; cursor envelope and client-default breaks are batched into one release-notes rewrite. Rollback per step is `git revert` of that step's PR — no step leaves persistent state behind (the only durable artifacts are recorded gate EDNs, which revert with the code).

## Open Questions

- Post-oracle, does any backend earn a `:managed` default? (Deferred until the randomized managed oracle has soaked in CI; requires the writer-contract story to be enforceable, not just documented.)
- Endpoint-local stamps for hot-relation invalidation precision — measure first on the new gates; only pursue if relation-granularity thrash is observed on a real workload.
- Adaptive tier sizing driven by the new avoided-backend-ops/eviction telemetry — follow-up change once the counters have production soak.
- Phase-2 batching trigger evaluation date — after D-2/D-3/D-9.1 land and the populated-recursion gate reports.
- AEAD portable-cursor unification (6.4) — deferred: requires an async client surface or a vetted vendored GCM; see the D-4 implementation-status note.
