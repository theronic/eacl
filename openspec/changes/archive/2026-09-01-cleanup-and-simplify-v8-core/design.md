## Goals / Non-Goals

**Goals:**
- Strictly less logical work per request on every touched path, proven by the existing deterministic-work and benchmark gates (which ratchet "at or below baseline").
- Every assurance gate either able to fail for the reason it claims to test, or deleted.
- Zero observable behavior change on valid inputs; error-surface changes confined to internal-corruption paths (see D5).
- All certification gates green at every tranche boundary, not just at the end.

**Non-Goals:**
- No algorithm or public-API changes; no wire/cursor/persisted-format changes.
- No namespace splits or renames of gate-listed vars (the 4,301-line `client/orchestration.cljc` god namespace and 455-line `permission_tree/expand` stay structurally intact — splitting them churns the 93-root list for zero behavior benefit; that is a follow-up change).
- No deletion of the dormant `IndexedTraversalKernel`/`portable-indexed` half or the 12 retired kernel operations from the Dafny surface, and no CLJS bundle recomposition (bundle-size policy literals gate it). Only their per-decide compare branches in `invoke-kernel` go.
- No deadline-granularity change: `execution/check!` keeps sampling the clock per invocation; only the success-path allocations and the dynamic-var-per-read go. Clock sampling every N transitions changes observable deadline behavior and is out.
- No CI job renames or removals (release-guard pins 9 check names); workflow edits are step-internal.
- No relaxation of attacker-facing validation: the four cursor `validate-*-bound!` fns, `secure-format/decode-authenticated`, `execution/normalize`, `batch/validate-request!`, and public-API admission checks are untouched (except hoisting their embedded plan-digest recomputation, which is input-independent).

## Decisions

**D1 — Remove the `expected-*` runtime oracle from `invoke-kernel`; keep the mandated FFI boundary and the O(1) bounds checks.**
`validate-input!`/`validate-result!` stay (assurance-contract `:boundary-invariants`; Dafny proves nothing about host marshalling), and so do the constant-work live-page bounds checks at `:2192-2209` (`:relationship-page` result within input bounds, `:relationship-keyset-page` take-count within size) — those are result validation, not re-derivation. What goes is `:2211-2329`: the `expected-*` equality re-derivations for the two live consistency operations and every dead-operation branch. On CLJS the oracle compares `portable-decisions` against itself; on the JVM it re-derives the answer per request. The same comparisons already run offline at scale (1000-case differential vectors, `production_kernel_test.clj` 1846 L, `state_trace_differential_test.clj`). *Alternative considered:* gate the oracle behind a var bound true in formal suites — rejected because it keeps two copies of eight decision functions in production source and the offline suites already provide the coverage; a test-installed wrapper kernel in the formal suites achieves the same observation without production residue. Consequence handled in D8: mutation kills that today can discharge through the oracle's boundary rejection must be proven to still fire afterwards. `normalize-selection` needs no change — it already fast-paths the `satisfies?` probe for the normalized production shape (`:2158-2164`, with an explanatory comment), leaving only a trivial allowlist per decide.

**D2 — Retain verified-but-dormant seams; delete only unreferenced code.**
The repo deliberately parks verified seams (`maximum-concurrent-snapshot-read-width` is documented as retained; `IndexedTraversalKernel` is differentially tested and staged). Deletion list is limited to items with zero references from prod, test, formal, docs, and build wiring — plus `datomic/codec` and `datomic/consistency`, which have only self-tests/anti-regression assertions that are updated in the same commit. `eacl.datomic.consistency` additionally appears in `bin/reflection-gate:25`'s pinned namespace list (verified), so that list is edited in the same commit as the deletion. Deleting the stale `exploration/stable-discovery` duplicates must honor `verify-fast.sh`'s header disposition: the *parked* concurrency models it names live only in `exploration/` on purpose and are not deleted; only the five files whose newer authoritative copies live in `formal/stable-discovery/` go. These two are removals from a published module's loadable surface; neither is documented in module READMEs as public API, and the module README/CHANGELOG records the removal.

**D3 — Seal plan-invariant derivations into the plan at compile time.**
`expression-roots` (rebuilt at 7 call sites incl. per batch — `check-cached-many-eids` and `check-many-eids` each call it again per invocation), `acyclic-plan?`, and `path-check-rank`-style orderings become fields computed once in `operator/plan.cljc:547-611`. The cover-plan seal memoizes into the existing `:sealed-plans` partition keyed exactly like `stable-plan` (`v8.cljc:1028-1044`), with `[permission root]` (plus the plan fingerprint for safety) as the memo key inside the schema-identity-scoped partition. This is legal because the sealed output is verified closure-free data: `sealed-plan/seal-plan` returns a plain map (`:nodes :rules :edges :certificate :order-contract :indexes :fingerprint …` — docstring: "Pure with respect to relationship data"), the wrapper adapter is used only during compilation and not retained, and `cover-plan/seal-plan` adds only three data keys — the exact precedent `stable-plan` already relies on. Digest stability: `cursor-scope/semantic-input` (`cursor_scope.cljc:10-35`) digests an explicit key list — added derived fields are outside the digest input, so cursor/scope identities are unchanged; the counterexample-replay and cursor suites verify this. *Alternative:* memoize per request in `*schema-cache*` — rejected for the plan-owned properties because the plan value is the natural cache and survives across requests.

**D4 — In-place refactors only; name-list edits ride the same commit.**
No public var moves. New shared helpers (deduped `add-stat!`/`invalid!`/`limit!`, shared adapter scan-option normalization) go in new namespaces, which the 93-root closure tolerates (roots stay put; closure follows requires). The 23 `with-redefs` mutation targets are checked against every touched var before editing; consolidations never relocate a target var. The duplicate `*aggregate-work-stats*` name is resolved by renaming the `stable_reducer` one (verified not in any gate list) with its test references in the same commit.

**D5 — Error-surface policy.**
Client-input validation behavior is frozen (`api-error-contract`). For the guard collapse, the binding authority is executable tests only: the counterexample ledger's `expected.edn` files are existence-checked, never parsed (verified at the replay test's artifact loop), so they are descriptive history, not gates — if reported wording legitimately changes, the edn is updated to match reality, never the code contorted to match unread documentation. Concretely: (a) the `exact?`+`natural?` collapse runs one combined predicate on the hot path; the failure branch (cold) reports whatever `ex-data` the EACL-FORMAL-027 closing regression (`runtime-guards-reject-negative-internal-eids-test`) and the guard tests actually assert — classify the `:obligation` keyword only if a test demands the distinction, otherwise one honest obligation value suffices and `expected.edn` is updated to describe it. (b) Removing Datalevin's adapter-level per-element `exact-natural!` (`datalevin/backend.cljc:249-273`) leaves detection to the engine's `guard-scan!`, changing the error type on corrupt backend data from `:eacl/numeric-domain-error` to `:eacl/backend-contract-violation` — the one accepted detail change, firing only when a backend returns non-natural eids (impossible through the public write path). Crucially the adapter's `mapv` also *realizes results inside the LMDB `with-db` scope*, which is mandatory — the replacement keeps eager realization (`vec`) and drops only the per-element guard. The `case direction :asc nil :desc nil` throw-only idiom in adapter scans becomes a typed error; unreachable via internal callers.

**D6 — Counterexample replay runs where all 67 entries resolve.**
The skip-on-missing-classpath tolerance is documented intent for module-isolated nREPLs and stays for those runs. The fix is a strict completeness mode (env/system-property flag) that asserts `(= (count entries) (count available))`, enabled in the one job meant to be the full replay gate — whose nREPL alias (`formal.yml:565`) gains `:formal-smoke` so all 67 entries resolve. The replay *entrypoint* rule ("no eager test-only loading") is unaffected: `requiring-resolve` stays lazy; only the classpath grows. *Alternative:* keep the ordinary classpath and accept 49/67 — rejected; a gate that silently skips is exactly the defect class this change exists to remove.

**D7 — CI wall-clock reductions that don't touch gate authority.**
(a) `browser-bundle` reuses `build-js` output instead of re-running `compile-js`+`npm ci` (verify `EACL-FORMAL-031`'s determinism expectation still holds). (b) The 49 Dafny verifies run in parallel (`xargs -P`-style) keeping one CSV per file so the per-basename `:minimum-proof-efforts` mapping is untouched. (c) The routing-certificate benchmark (gates a production-dead operation) moves from per-push to the existing weekly cron alongside `apalache-scheduled`. (d) `verify-fast.sh` (the *shipped* engine's 651-obligation gate, currently never executed by CI) joins the weekly cron; its 12 s wall-clock hard limit becomes a generous constant or is dropped in CI mode (wall-clock hard limits are inherently flaky; the obligation count and fingerprint checks are the real gate). Every formal.yml edit updates `characterization_fixture_test.clj`'s pinned step names/ordering in the same commit. Full-suite duplication across `Tests` and the authority suite is retained — the authority suite's counting kernel is its point, and release-guard pins both checks.

**D8 — Mutation controls become genuinely falsifiable.**
Mechanism today (verified): `portable-mutation-killed?` redefines `portable/decide` to the mutant and re-runs `verified/decide` — the kill fires when the mutant result differs from the adjacent `expected` literal *or* when `invoke-kernel` rejects the mutant (caught as killed). The first path is decidable from the two literals; for six operations the second path runs through the `expected-*` duplicate of the mutated function. Repair in two steps: (1) immediately after oracle removal (D1), prove all 15 controls still kill via the literal path — an intermediate gate, not the end state; (2) strengthen `argument-ignoring-constant-fn?` to reject any binding whose body ignores its arguments (named params included) and re-deliver each kill through the gate the registry claims (differential suite, property test, or replay) rather than through adjacent literals, with `mutation_control_test` proving detection per row. The empty-set Apalache gate gains a minimum-mutant-count assertion sourced from the registry (mirroring the replay gate's count check).

**D9 — Concurrency-safe locality rules for state downgrades.**
`atom` → `volatile!` only where the reference provably never escapes its thread: `vector_evaluator.cljc:145-150` and `permission_tree.cljc:256-262` (request-local, single-threaded evaluation loops — matching the file-internal precedent at `evaluator.cljc:209`, `stable_route.cljc:106` (already `volatile!`), `seekable.cljc:278`, `recursive.cljc:97`). Verified: `modules/eacl/src` contains no `pmap`/`future`/executor/`core.async` usage — request evaluation is single-threaded today; the repeatedly-documented "future concurrency change" SPI would have to revisit these downgrades, which the code comments already anticipate. Anything reachable from a cache, store, or observer var stays an atom. Transients only inside single-owner builder scopes, per existing correct usages.

**D10 — Tooling.**
`.clj-kondo/config.edn` gains a hook/`:lint-as` for `with-request-engine` (kills the false "Unresolved symbol: adapter" error at `datomic/impl.clj:54`) so real errors stop drowning; the 22 current warnings (unused bindings, `(not (empty? …))`, unused private vars) are fixed at source. Stale `:refer-clojure :exclude` entries (`execution.cljc:8` `next`, `subproblem_cache.cljc:8` `resolve`, `request/counters.cljc:8` `reset!`) are removed — they silently break core-fn use in those namespaces.

## Risks / Trade-offs

- [Sealed-plan shape change perturbs a cache or digest] → derived fields are additive and outside the explicit digest key list (verified against `cursor-scope/semantic-input`); run cursor, replay, and cache suites in the same tranche; `stable-plan`'s existing partition keying is reused unchanged.
- [Removing the runtime oracle weakens in-production drift detection] → detection authority was already offline (differential suites, crossing-count gates); the oracle detected only kernel-vs-duplicate divergence, and on CLJS detected nothing by construction. Mutation-control re-pointing (D8) proves the offline gates fire. The CLJS bundle gates are ceilings plus forbidden-marker checks (verified in `formal/policy/cljs-production.edn` `:release-invariants`), so the resulting bundle shrinkage passes without policy edits; re-recording `:reference-observations` is optional.
- [A refactor silently detaches a mutation `with-redefs` target or consumer claim] → the registry's target/consumer symbol lists were checked against every planned edit: no planned change moves or removes a target var; `batch/aggregate-counters` is a target whose request-level production call is deliberately retained by the batch-counters task; tranches touching `stable-reducer/*`, `direct/*`, or `batch/*` run `eacl.formal.mutation-control-test` in their verification.
- [Clock capture changes behavior for tests that rebind `*monotonic-nanos*` after contract creation] → the verified test pattern binds at `execution/normalize` (and re-binds the same closure around `check!`); the tranche sweeps all ten test files that bind the var and fixes any that create the contract outside the binding before the capture lands.
- [Mutation-registry edits break `formal-implementation-conformance` gates mid-change] → each registry edit is paired with its detector change in one commit and verified by running `eacl.formal.mutation-control-test` before moving on.
- [Datalevin tranche is under-tested because the module is off the root classpath] → run `:datalevin-test` explicitly (requires the local `../datalevin` checkout per `deps.edn`); if unavailable in the environment, the Datalevin guard-dedup tasks are skipped and reported, not silently assumed.
- [Deleting the nested `worktrees/eacl` copy corrupts git worktree metadata] → check `git worktree list` first; if registered, `git worktree remove`/`prune`; otherwise plain delete. (Read-only git commands only in `core` per repo convention; no `git add`/`commit` outside explicit user instruction.)
- [In-flight changes conflict (`standardize-authorization-cache-storage`, `adopt-stable-discovery-enumeration`)] → before cache/engine tranches, diff-check the touched files against those changes' task lists; sequence cache-adjacent work last.
- [`characterization_fixture_test` pins formal.yml text and step order] → every workflow edit updates the fixture assertions in the same commit and runs that test locally.
- [Behavior drift hiding in "identical" refactors] → tranche discipline: full CI-equivalent battery (nREPL, per AGENTS.md) plus `bin/formal source-closure` after each tranche touching public roots; benchmark/deterministic-work gates compared against pre-change baseline captured in tranche 0.

## Migration Plan

Internal refactor; no deployment or data migration. Each tranche is an independently revertible commit series on a feature branch; a tranche that fails its gates is reverted or fixed before the next begins. Rollback = `git revert` of the tranche commits.
