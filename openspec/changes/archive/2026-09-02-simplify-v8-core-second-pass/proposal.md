## Why

The first cleanup pass (`2026-09-01-cleanup-and-simplify-v8-core`) removed the safest additive machinery, but a fresh line-by-line survey of the five production source roots against `.rules/clojure-rules.md` found that it left the hottest loops largely untouched, marked several tasks done that were not, and introduced one regression: its unification of the stable-route count option keys dropped `:cut-point!`, so deadline and cancellation checks no longer ran during exhaustive counts. Per-tuple and per-candidate work that is invariant per plan, per batch or per request remained everywhere — bit masks mutated per resolved candidate only to feed an optional stats var, the recursive solver re-sorting already-sorted components with `pr-str` on every fixpoint round and re-condensing the graph after the demand loop, a SHA-256 checkpoint digested twice per batch and discarded, per-datom subvector allocation in every backend's prefix matcher, an eager 20-key counter aggregate per scanned relationship, and a request-counter fast path defeated by every nested `binding`. A second behavior-preserving pass takes each of these to the boundary that already establishes the invariant, deletes what the first pass left dead, and repairs the assurance harness where its evidence was stale or never executed.

## What Changes

- **Operator engine hot loops**: the vector evaluator's aligned masks become a projection of the memo row, derived only when an observer is bound; the scalar evaluator keeps one deadline check per transition; candidate normalization validates the closed key set without allocating one and skips the duplicate scan for a single candidate; cached point decisions merge positionally; the recursive solver iterates components in the order the SCC pass already produced, returns its condensation for the exact pass, digests the checkpoint once and only when a caller asks for it, attaches base probes with one decorated sort and rewrites only touched questions; operator-path arrow scans carry `:limit` so natively paging adapters stop at the chunk; the seekable page runs one deadline check per scan; the acyclic count route reuses the memoized cover seal.
- **Engine facade and stable engine**: one routed envelope, one least-path/stable-page option builder, one recursive batch evaluator and one count pipeline for both directions; the host copy of the generated page normalization is folded into the kernel call; the count-route cut-point regression is fixed through one shared `^:no-doc` reducer option-key list with a regression test; `:pre` assertions that duplicated the typed client boundary are removed from the engine entry points; witness probes stop re-attaching plan and subject type per candidate; sidecar retention commits in two record revisions; stats reporting allocates nothing when unobserved; least-path machines share one sealed-order helper.
- **Backends**: the shared endpoint prefix predicate and Datahike's three copies compare component-wise; scan options that name their direction pass through the normalizer unchanged; Datomic's scan pair collapses into one lazy endpoint scan, reads relation definitions from the composite tuple index and drops the identity-facade override seam; Datahike resolves per-db identities and the storage stamp once per adapter and reads the execution contract once per batch; Datalevin's eager scan drops only an exclusive boundary row, resolves numeric ids without a read scope and loses dead helpers; the relationship cursor is normalized once per scan in all three Datalog backends.
- **Client, kernel boundary and caches**: per-candidate deadline diagnostics become thunks; the request-counter ledger cache re-keys itself to nested binding frames; permission-tree expansion reads memos once, drops a duplicate cycle check and renders leaves directly; the generated-kernel boundary checks closed key sets and the production selection map without allocating; the reflective virtual-thread probe resolves once per process; the subproblem cache skips option scans for its constant maps; the exact denotation key builds its source identity once per request; relay observes the deadline around the identity batch; the proof frame reads before it swaps; non-default expression-limit profiles are normalized once per bound object.
- **Dead code**: unreferenced vars in the core module (`orchestration/can?`, `physical/telemetry`, `sealed-plan/local-read-cost`, `recursive/check-eids`, `endpoint-pair/half-identity`, `batch/root-key`, `expression-policy/compatibility-digest`, `expression-resolver/resolve-definitions`), Datomic facade wrappers and override keys, Datalevin helpers orphaned by the earlier integrity-namespace removal, a dead edge-page option, the never-taken inner validation guards, and the duplicate merge-sort oracle on the shared smoke classpath.
- **Assurance harness**: the release-assurance manifest gate, never executed by CI, now runs in the Dafny job with its documented "conditionally verified" exit accepted; the dormant CLJS indexed-traversal scaling gate moves to the scheduled runs like the routing-certificate gate; the fast stable-discovery verifier reads its tool versions from the checksum lock; the browser-bundle freshness guard watches the JavaScript runtime patches; the assurance contract and docs carry the locked whole-tree count of 9384 proof efforts the last kernel revision left behind.
- **Not changed**: algorithms, public APIs, wire/cursor/persisted formats, the Dafny/TLA proof surface, adapter certification obligations, CI job names, mutation-registry targets.
