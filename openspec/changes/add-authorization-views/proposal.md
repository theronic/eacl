## Why

EACL's public `IAuthorization` client fuses three things that have different lifetimes: an immutable database basis (a value), the live source that can find another basis (a connection), and the transactor that can produce one (a writer). Every public read therefore starts by asking the connection for "current", even when the caller already holds the exact immutable value it wants to evaluate against. On a Lambda-based Peer whose Datahike or Datomic history lives in S3 or DynamoDB, "current" is a remote branch-head read; the 2026-08-22 MinIO baseline in `eacl-datahike-demo` measured five branch-head GETs for one warm permission check and zero after one captured `db` value was reused. The only way to reuse a value today is the private orchestration `api`/`opts` surface or the Datomic engine facade, neither of which carries caches, authenticated cursors, consistency validation, or lifecycle.

EACL v8 is unreleased. This is the moment to make the reader/writer separation a foundational assumption: an immutable **snapshot** is the primary authorization target, a live **acl** is a snapshot source plus an optional writer, and nothing that can only read is able to reach a connection.

## What Changes

- **BREAKING** Replace `IAuthorization` and `IDetailedAuthorization` with four capabilities: `IAuthorizationReader` (canonical request-map reads), `IAuthorizationWriter` (canonical mutations), `ISnapshotSource` (consistency → snapshot), and `IAuthorizationSnapshot` (basis metadata and lifecycle). `check-permission` becomes the canonical decision; `can?` is its boolean projection.
- Add the public immutable **snapshot** value: one selected backend database value, its authenticated basis identity, and the owning `acl`'s shared runtime. It holds no connection, source, or writer. Every `eacl/*` read function accepts either an `acl` or a snapshot.
- Add `eacl/snapshot` (capture current once, or select by an explicit consistency descriptor), per-backend direct constructors over an application-owned database value (`eacl.datomic.core/snapshot`, `eacl.datahike.core/snapshot`, `eacl.datascript.core/snapshot`), `eacl/with-snapshot`, `eacl/release!`, `eacl/basis`, `eacl/basis-token`, and target predicates.
- Make every read on an `acl` select exactly one transient snapshot and execute entirely against it; a retained snapshot never re-selects. Both paths enter the shared `eacl.request.context/make-context` seam. Consistency is request-scoped on `acl` and a validated assertion on a snapshot.
- Split the backend SPI into three roles with separate construction-time certification: a **basis adapter** that reads one immutable database value, a **basis source** that selects bases from a connection (current, authoritative, at-least, exact-by-locator) and owns native lifecycle, and a **writer** that submits transactions. Constructing an `acl` acquires nothing; exact selection by locator reads no current head.
- Make the cache model basis-first: one exact tier keyed by complete basis identity without `:schema-identity`, bounded retention across bases (replacing the separate exact-current and snapshot-exact tiers), per-basis subproblem stores, managed proof-backed lifting governed by basis class and history direction rather than by consistency mode, and runtime-owned (not process-global) plan and schema registries keyed by `[engine ABI backend source scope lifecycle certified schema generation]`.
- Classify database values by **basis kind** at admission: ordinary and as-of values are admissible; filtered, since, history, and speculative values are refused by public snapshot constructors and remain engine-facade-only.
- Move Datomic onto the shared orchestration. `Spiceomic`, its private cursor codec, page cache, and duplicated cache wiring are deleted; Datomic contributes adapter, source, and writer implementations, and its CAS retry and batched deletion become writer-declared behaviour of the shared write pipeline.
- Unify the error taxonomy: one `:eacl/unsupported-capability` for every target/capability mismatch, `:eacl/snapshot-released`, `:eacl/unsupported-database-value`, `:eacl.consistency/selection-required`, `:eacl.consistency/freshness-unavailable` with reason `:snapshot-behind`, and `:eacl.consistency/basis-conflict` for exact tokens and cursors that name another basis.
- Make the default source lifecycle a documented constant for Datomic, Datahike, and DataScript so tokens and cursors round-trip between reader and writer processes without configuration. Datalevin keeps its required, explicitly supplied persisted lifecycle; rotation remains the explicit operator action on history replacement.
- Keep Datalevin source acquisition on the maintained fork's revision-only `read-snapshot-revision-info` seam. The source obtains `:max-tx` and `:max-eid` without requesting full snapshot metadata or physical schema; the allocation benchmark and release gate remain owned by `eliminate-authorization-request-amplification`.
- No compatibility shims, aliases, or migration interval. The in-workspace `eacl-spicedb` adapter is recut against the new reader/writer protocols as coordinated follow-on work.

## Capabilities

### New Capabilities

- `authorization-snapshots`: the public immutable snapshot value, unified `eacl/*` dispatch over `acl` and snapshot, capture/select/direct construction, basis kinds, basis metadata and tokens, consistency assertions, read/write capability separation, cache-class sharing, cursor continuation across targets, lifecycle and thread affinity, lifecycle rotation, and cross-process basis exchange.

### Modified Capabilities

- `backend-unification`: shared orchestration over three backend roles (basis adapter, basis source, writer); uniform construction that acquires nothing; a shared write pipeline with writer-declared retry and batching.
- `backend-native-revision-consistency`: selection belongs to sources and returns snapshots; retained snapshots validate but never select; exact selection by locator performs no current-head read; built-in borrowed-basis backends use a documented default lifecycle, Datalevin requires an explicitly persisted lifecycle, and rotation is explicit.
- `forward-history-cache-coherence`: the exact-current and snapshot-exact tiers become one exact-basis tier with bounded retained bases; managed lifting is governed by basis class and direction rather than by `:at-exact-snapshot`; basis kind is part of exact identity.
- `dependency-validated-authorization-cache`: lifting is defined against the selected basis rather than "the current snapshot", scoped to one lineage (source scope and lifecycle) and independent of revision direction.
- `datascript-current-basis-consistency`: per-request current capture applies to reads through an `acl`; a caller-retained DataScript snapshot evaluates at its own immutable value; cursors continue on the selected basis.
- `cross-backend-conformance`: the shared suite runs every read over writable `acl`, read-only `acl`, captured, selected, and direct snapshots, and proves acquisition counts, concurrency stability, lifecycle, thread affinity, and cross-process token round trips.
- `api-error-contract`: capability-complete targets, one unsupported-capability classification, and typed pre-evaluation failures for snapshot assertions and lifecycle.

## Impact

- `modules/eacl/src/eacl/core.cljc` (protocols, public functions, records, `with-snapshot`), `eacl.client.orchestration` (becomes the shared `Acl`/`Snapshot` implementation), `eacl.consistency`, `eacl.backend.v8` (adapter role only), `eacl.backend.snapshot-provider` (becomes the source role), a new writer role, `eacl.cache`/`eacl.subproblem-cache` (exact-basis tier, retained bases), `eacl.engine.v8` (runtime-owned plan and schema registries), `eacl.relay`/`eacl.cursor` (continuation dispatch by target).
- Datomic, Datahike, DataScript, and Datalevin modules: adapter/source/writer implementations, `snapshot` constructors, native accessors, basis-kind classification; Datalevin source acquisition consumes the maintained fork's revision-only snapshot metadata API. `eacl.datomic.core/Spiceomic` and its private orchestration are deleted; `eacl.datomic.impl` remains the engine facade.
- Formal assurance artifacts: `formal/verification/execution-contract.edn`, `assurance-matrix.edn`, `implementation-simplicity.edn`, `production-decision-inventory.md`, `public-source-closure.json`, the adapter-obligation mapping to `formal/dafny/SnapshotOracle.dfy`, and the lifting-direction statement in `NativeGenerationCoherence.dfy`.
- Tests: shared conformance matrix by target kind, acquisition-count instrumentation, lifecycle and thread-affinity suites, cross-process token round trips, Datomic characterization/op-count/plan-isolation suites retargeted to the shared pipeline and the engine facade.
- Documentation: README quickstarts stay one `make-client` call; a "Snapshots" section adds capture, select, direct construction, and the Lambda session-basis pattern; `docs/v8-backend-adapter-boundary.md`, `docs/v8-consistency-cache-operations.md`, `docs/cache.md`, and `docs/release-notes-v8.0.md` are rewritten for the three roles and the basis-first cache model.
- Downstream: `eacl-spicedb` (protocol recut), `eacl-datahike-demo` (replace the private `orchestration/make-client` bridge with `snapshot`; its `pin-serverless-datahike-session-bases` change consumes this API), `eacl-datomic-solidjs`/`eacl-edrive` (unchanged; they use `eacl.datomic.impl` transaction helpers only).
