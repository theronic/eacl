## Heavy pagination/load suite

The first runnable baseline found that the existing latency assertions mixed
two different costs:

- the intended traversal/cache algorithm cost; and
- default unknown-writer content proofs, which hash complete dependencies before
  a cache/cursor decision.

On the 15,000-server fixture, content-proof mode was approximately 665–676
ms/page and `can?` was 5–9 ms. Raising traversal gates to those values would
have hidden traversal regressions. The suite now establishes managed
mutation-proof authority only after all static direct fixture writes, and the
dedicated proof-strategy benchmark retains explicit content-proof measurements.

Managed traversal baseline:

- first 50-item page median: 1.43 ms;
- forward 40-page/8-run maximum page median: 1.98 ms;
- reverse maximum page median: 1.62 ms;
- deep-page medians: 1.38 / 0.89 / 0.62 ms;
- relationship EIDs realized at first/middle/last depth: 633 / 325 / 220;
- relationship scan calls: 282 / 86 / 79.

Recursive 4,000-node baseline:

- continuation walk: 4,159 derived grants, 74.68 ms;
- deterministic replay: 322,159 derived grants, 1,393.72 ms;
- completed-page walk: 0 derived grants, 50.51 ms;
- replay/continuation work ratio: 77.46×;
- replay/continuation time ratio: 18.66×.

Retained memory/work guards:

- 20,000-result count miss uses 2 pages;
- maximum retained page is 16,384 EIDs;
- rejected admission leaves no full-result cache entry;
- completed recursive pages perform 0 stores.

A five-trial, GC-stabilized 4,000-result recursive walk retained between
-3,760 and +4,648 bytes relative to the seeded client (median -3,440 bytes).
The sign and small magnitude show that `MemoryMXBean` noise dominates this
micro-measurement; it is recorded as a baseline, not treated as a portable
heap proof. The deterministic memory gates are the 16 MiB default bounded
continuation-store weight and the 16,384-EID retained-page ceiling.

Generated authenticated page-token sizes were:

- 1,814 UTF-8 bytes for a recursive 250-result fixture with page size 25;
- 1,966 UTF-8 bytes for a 500-result multipath fixture with page size 50.

The quantitative regression and staged shadow gates derived from these
measurements are machine-readable in `performance-gates.edn`.

Proof strategy on the small churn fixture, median microseconds/read:

| History | Mutation proof | Content proof | Global invalidation | No cache |
| --- | ---: | ---: | ---: | ---: |
| Unrelated writes | 1,250 | 1,461 | 586 | 182 |

Security/accounting overhead changed the old `can?` microbenchmarks. The new
host-calibrated regression ceilings retain about 3× headroom:

- managed warm `can?`: 1,000 µs ceiling (268 µs baseline);
- managed cold-path `can?`: 1,500 µs ceiling (268 µs baseline);
- authenticated completed-cache `can?`: 3,000 µs ceiling (1,616 µs baseline).

These are regression alarms, not proof claims or portable service-level
objectives. Release cutover must measure representative deployment hardware.

## Bugs found in this baseline

The minimized, fixed witnesses are `EACL-FORMAL-001` through
`EACL-FORMAL-005`:

1. heavy benchmark schema initialization order;
2. unreachable recursive continuation optimization causing quadratic replay;
3. authenticated cache erasing logical admission kind;
4. proofless cursor mixing snapshots across pages;
5. CLJ/CLJS portable cursor expiry boundary differing from Datomic.

Each corpus entry names its failing regression and closing proof/test.
